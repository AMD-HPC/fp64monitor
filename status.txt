  FP64 Monitor Tool Summary



  Overview

  The FP64 Monitor is an LD_PRELOAD-based profiling tool for AMD GPUs that samples hardware performance counters at periodic intervals to
  monitor FP64 (double-precision) instruction usage and memory consumption in HIP applications. It's designed for HPC workloads where
  understanding the FP64 instruction mix is important for performance analysis.


  Key Features

  • Periodic sampling of GPU hardware counters (configurable interval, default 1Hz)
  • FP64 instruction breakdown: ADD, MUL, FMA, transcendental, and MFMA operations
  • Memory monitoring: GPU memory (HIP API), VRAM/GTT (ROCm SMI), and CPU memory (/proc/self/statm)
  • High water mark tracking for all memory types
  • MPI support: Unique output files per rank with %r, %p, %h filename patterns
  • Automatic analysis: Aggregates data across MPI ranks into a single summary
  • Cross-ROCm compatibility: Works with both ROCm 6.x and ROCm 7.x

  Usage


  # Basic usage with wrapper script
  FP64_MONITOR_INTERVAL=100 srun -n 4 --gpus=4 --gpus-per-task=1 \
      ./fp64_monitor.sh ./my_hip_app
  # Direct LD_PRELOAD usage
  FP64_MONITOR_OUTPUT=output_%r.csv \
  LD_PRELOAD=./libfp64_monitor_tool.so ./my_hip_app
  # Manual analysis of multiple rank files
  python3 analyze_results.py fp64_monitor_*.csv

  CSV Output Columns

  Instruction counters: total_instructions, valu_instructions, fp64_add, fp64_mul, fp64_fma, fp64_trans, fp64_mfma, fp32_*, fp16_total,
  mfma_total, etc.
  Percentages: fp64_valu_pct, fp64_total_pct, fp64_compute_pct, mfma_fp64_pct
  Memory (MB): gpu_mem_used_mb, gpu_mem_total_mb, vram_used_mb, vram_total_mb, gtt_used_mb, gtt_total_mb, cpu_resident_mb, cpu_virtual_mb,
  plus *_hwm_mb high water marks


  ROCm Compatibility

  The tool uses a compatibility layer (rocprofiler_compat.hpp) to handle API differences:

  ┌─────────────────┬──────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Feature         │ ROCm 6.x (rocprofiler-sdk 0.6)           │ ROCm 7.x (rocprofiler-sdk 1.x)                         │
  ├─────────────────┼──────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Config ID type  │ rocprofiler_profile_config_id_t          │ rocprofiler_counter_config_id_t (aliased)              │
  │ Config creation │ rocprofiler_create_profile_config        │ rocprofiler_create_counter_config (deprecated wrapper) │
  │ Counter record  │ rocprofiler_record_counter_t             │ rocprofiler_counter_record_t                           │
  │ Instance count  │ rocprofiler_query_counter_instance_count │ rocprofiler_counter_info_v1_t                          │
  └─────────────────┴──────────────────────────────────────────┴────────────────────────────────────────────────────────┘

  Known Limitations

  1. FP64 percentage interpretation: Even "pure FP64" kernels show ~10-15% FP64 VALU due to address calculations and loop control overhead
  2. Counter permissions: May require CAP_SYS_PERFMON for accurate PMC counters
  3. ROCm SMI on ROCm 6.x: Requires system libdrm-dev package (bundled in ROCm 7.x TheRock builds)
  4. Cumulative counters: Values accumulate from context start; analysis uses deltas

  4. Fixed Critical Shutdown Crash in `fp64_monitor_tool.cpp`
  The tool was crashing during shutdown with rocBLAS applications. Root cause analysis:
  • Problem 1: terminate called without an active exception - Thread destructor called on joinable thread
  • Problem 2: Segfault during sampling_thread->detach() with rocBLAS

  Key Discovery: With rocBLAS, the output file was already closed when tool_fini was called (is_open() returned false), indicating corrupted
  state from rocBLAS/rocprofiler cleanup interaction.
  Solution: Use output_file->is_open() as a proxy for state validity:

  bool file_valid = g_state.output_file && g_state.output_file->is_open();
  if (file_valid) {
      // Write summary - safe to use file and mutexes
  }
  // Only touch thread if state is not corrupted
  if (file_valid && g_state.sampling_thread && g_state.sampling_thread->joinable()) {
      g_state.sampling_thread->detach();
  }

  5. Updated Wrapper Script (`tools/fp64_monitor.sh`)
  • Changed from LD_PRELOAD to ROCP_TOOL_LIBRARIES for better rocprofiler-sdk compatibility
  • Fixed library search paths for tools/ directory location
  • Verified working with both ROCm 6.4.3 and ROCm 7.13
